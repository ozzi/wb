# Офис: термостат не греет в часы пика тарифа

Правило `rules/office-tariff-window.js` (wb-rules, деплой — RPC `wbrules/Editor/Save`).
Тест: `node tests/office-tariff-window.test.js`.

## Зачем

Офис отапливается электроконвектором 1 кВт (реле `wb-mr6cu_91/K1`, учёт — MAP12E `Ch 2`).
При трёхзонном тарифе час пика стоит вдвое дороже ночи, и греть самой дорогой зоной
незачем: помещение нежилое в это время и спокойно переносит паузу.

Предпикового перегрева нет — по решению владельца правило только выключает и включает.
Уставку сценария (10 °C) правило не трогает.

## Зоны (трёхзонный тариф)

| Зона | Часы | Что делает правило |
| --- | --- | --- |
| пик | 08:00–11:00, 20:00–22:00 | сценарий выключен, реле отпущено |
| полупик | 07:00–08:00, 11:00–20:00, 22:00–23:00 | сценарий работает |
| ночь | 23:00–07:00 | сценарий работает |

Пик — 5 часов в сутки.

## Что делает

Не считает температуру само: включает и выключает **правило сценария** `wbsc_office2`
(`rule_enabled`), поэтому второго регулятора на реле не появляется. В окне пика сценарий
выключается, а реле отпускается принудительно — выключение `rule_enabled` само актуатор
не гасит.

Витрина `office-tariff-window`:

| Канал | Тип | Кто пишет |
| --- | --- | --- |
| `enabled` | switch | человек: вся логика целиком |
| `manual` | switch | человек: ручной режим до конца суток, сбрасывается при смене даты |
| `heating_allowed` | switch, readonly | правило: 0 в пике — этим же каналом подавляется сторож сценария |
| `zone` | text, readonly | правило: `пик` / `полупик` / `ночь` |
| `reason` | text, readonly | правило: почему нагрев разрешён или запрещён |
| `next_event` | text, readonly | правило: ближайшая граница, например `отключить нагрев 20:00` |

Правило **не** меняет уставку, не трогает датчики и не вмешивается в курятник.

## Взаимодействие со сторожем сценария

`scenario-keepalive.js` для офиса подавляется каналом `office-tariff-window/heating_allowed`
(так же, как курятник — каналом `kuryatnik-termo-dayoff/heating_allowed`). Без этого сторож
воспринял бы выключение в пике как ручное или аварийное и вернул бы нагрев в самый дорогой час.

## Проверка

```bash
# зона и причина
mosquitto_sub -h localhost -t /devices/office-tariff-window/controls/zone -C 1 -W 3
mosquitto_sub -h localhost -t /devices/office-tariff-window/controls/reason -C 1 -W 3
# состояние сценария и реле
mosquitto_sub -h localhost -t /devices/wbsc_office2/controls/rule_enabled -C 1 -W 3
mosquitto_sub -h localhost -t /devices/wb-mr6cu_91/controls/K1 -C 1 -W 3
```

В пике ожидается `heating_allowed = 0`, `rule_enabled = 0`, `K1 = 0`. Вне пика —
`heating_allowed = 1`, `rule_enabled = 1`; реле ходит по гистерезису вокруг 10 °C.

## Откат

- Мягкий: `enabled = 0` на витрине — сценарий работает как до правила, автоматика цела.
- Полный: `wbrules/Editor/Remove` с `{"path": "office-tariff-window.js"}`; в `scenario-keepalive.js`
  вернуть `inhibit: null` для офиса, иначе сторож уйдёт в `NO_CONFIG`.

## Ловушки

- Писать в VD только при изменении значения: иначе каждое тиканье публикует пакет, а
  MQTT-триггер в HA срабатывает на каждое сообщение в топик, а не только на смену значения.
- Время считать как `Date.now()` + смещение UTC+4: часовой пояс контроллера может быть
  Europe/Moscow.
- Не публиковать в `/devices/wbsc_office2/controls/rule_enabled/on` из своего скрипта: ломает
  persistent storage сценария. Только `dev[...]` из wb-rules или витрина в HA.
- `climate.office_climate = heat` в HA означает `rule_enabled = 1`, а не работу нагрева:
  фактическое включение видно по реле `K1` и `actuator_status`.
